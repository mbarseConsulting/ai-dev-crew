# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the repository follows [Semantic Versioning](https://semver.org/) as a whole. Entries dated before the move to `.claude/` refer to the former per-plugin versioning and are kept as an accurate record of what happened; they are not rewritten.

## [Unreleased]

### Changed

- **`crew-maintenance` becomes `crew-builder` ([ADR 0018](./docs/adr/0018-crew-builder-templates.md)).** It gains `-n <kind> <name>`: a techno, a `bp`, a `dom`, a `proc` or an agent is created from its template in `crew-builder/references/tpl-*.md`, wired where it loads, declared in the manifest and the watch sources, and checked by the doctor — six fixed steps. Rules never enter under `-n`: they come through `-w`, which now launches one `sonnet` subagent per target with the target file and its feeds. The templates leave `docs/doctrine.md` for files the builder copies.
- **One template per kind of file, everything in English.** A knowledge file (techno, `bp-`, `dom-`) is one `MUST` list and one `NEVER` list, each rule carrying its why as a trailing clause; the `## Règles` / `## Pourquoi` split is gone. A procedure file (`proc-`) is numbered steps. Both templates live in `docs/doctrine.md`, which shrinks to three things: where a rule goes, a skill names no other skill, the templates. The paste-window size rule, the agent-existence rule and the two-sources contract are dropped. All files in `.claude/` are in English; the project template's `Références de domaine` field becomes `Domain references`.
- **`technos/spring.md` replaces `java.md`, `java-spring.md` and `java-persistence.md`.** A techno is named after the framework, not the language. `angular-patterns.md`, an empty stub, is absorbed into `angular.md`. The crew loses two thirds of its words (18 855 → 7 838) without losing a rule.
- **Roles hold one intention each.** The dev develops, writes the tests (TDD when it fits, at least 80% of the changed lines covered), re-reads its own diff, runs the tests it wrote once, and never the suite. The tester runs the full suite and fixes what is red. The reviewer is an outside eye on the techno, the references and the security baseline, and gives a verdict. The butler asks how many devs, a tester, a reviewer, launches, gates and relays. The dev's nine steps, repair budget and evidence-report contract are gone; the tester's 3-cycle budget stays.
- **Watch moves out of `crew` into `crew-maintenance`; references are prefixed by nature ([ADR 0017](./docs/adr/0017-crew-maintenance-out-of-crew.md))**. `crew-maintenance` (`-d` repairs the structure through `crew-doctor`, `-w` watches) is never copied to a client; it is the only skill allowed to name `crew`. `crew` loses `-w`. The folder says the nature, the prefix the topic: `technos/<techno>-*.md` for a framework sub-topic, `references/bp-*` for shared best practices, `dom-*` for a domain, `proc-*` for role procedures. Technos lose their duplicates and their non-specific rules: new `bp-code`, the BFF pattern becomes `bp-bff`, `technos/node-bff.md` becomes `technos/node.md`, empty. `docs/doctrine.md` is the only description of the layout; `crew-doctor` checks prefixes and loading.
- **One `crew` skill: roles are its agents, technologies its technos ([ADR 0016](./docs/adr/0016-one-crew-skill-role-as-mode.md))**. `crew-dev`, `crew-review`, `crew-test`, `crew-watch` and `crew-architecture` merge. `crew/agents/` holds the roles (`agent-dev`, `agent-tester`, `agent-review`, `agent-butler`), `crew/technos/` the stacks, each listing its references. `/crew` detects the techno and loads `agent-dev` by default; `-t`, `-r`, `-b`, `-a` pick another role, `-c` launches it as a subagent. Reason: the rule "a skill names no other skill" left review, test, watch and architecture without the stack knowledge they depended on.
- **One verb per role**: the dev develops, the tester runs the full suite and fixes red tests listing every modified file, the review reads and gives a verdict (approve / approve with suggestions / changes requested), the butler orchestrates. Only the butler launches other agents.
- **Agents**: `.claude/agents/` keeps only 4 launchable shells that preload `crew` through `skills:`; the `agent-crew-*` and `agent-{java,angular,node-bff,python}` shells are removed.
- **Independence guard**: `-t` or `-r` in the conversation that wrote or briefed the same change (`-d` or `-b`) produces a "Self-check — not the gate", never a verdict.
- **Cross-cutting references restored**: `layering`, `api-rest`, `kafka` and `ws` had vanished from `crew/SKILL.md`'s shared table at the merge; Java and the BFF no longer loaded them. `crew-doctor` no longer counts a "Do NOT use" mention as a load and checks the manifest counts.
- **Mechanical detection**: the BFF is recognised by its HTTP dependency (`express`, `fastify`, `koa`, `hono`, `@nestjs/core`), Python by `fastapi`; `.scss`/`.css` go to Angular; a file matching no row stops the work.
- **Butler never as a subagent**: `-c` is ignored for `-b` and `-a`.
- **`testfix`**: undetermined runner → stop and report, no impossible question for a subagent.
- **`crew-project`**: `create` writes the project file and its row in `index.md`, whose format is defined; the four shells preload it.
- **`references/testfix.md`**: Maven, Gradle and pytest; the most specific target wins; disabling a test to go green is forbidden.
- **Detection** on the build file nearest to the changed file, not the repository root.
- **A skill names no other skill** (`c7b8557`) and **`crew-project` brought back** (`7863f65`, `cda2052`): ratified by ADR 0016.
- **Tooling**: `scripts/crew.sh` removed; `scripts/crew-doctor.sh` rewritten as a structural check, run by the versioned hook `.githooks/pre-commit`.
- **`crew-project` added** (6th skill). `crew-dev`'s Step 0 pointed to a profile nothing produced: deferring the generator while keeping the reference left a dead dependency, against the principle that a skill works alone. `crew-project` creates, updates and validates a profile — **outside the library and outside the client repository**, its main NEVER rule. The template moves from `docs/templates/` to `crew-project/templates/`, because a standalone skill carries its own files.
- **Library / project boundary, and a third axis of references ([ADR 0015](./docs/adr/0015-library-project-boundary-and-domain-axis.md))**. `house-rules.md` lived in `crew-dev/references/`: gitignored, but in the tree — so an employer's internal conventions travelled with the library on a machine change, or got lost. `.gitignore` was treating a portability problem as a publication problem. The rule is now explicit: **the library holds only what follows its owner for life**; everything project-specific lives outside and is *pointed to*, never *contained*.
- **`references/iot.md`** — first business-domain axis. ADR 0013's placement rule extends: *a rule belongs to the domain if it disappears when the domain changes*. "A consumer must be idempotent" survives → `kafka.md`; "carry the device clock **and** the server clock" does not → `iot.md`. Covers the two clocks, intermittent connectivity as the nominal case, bounded cardinality, revocable per-device identity, additive schema for life (a fleet is never fully online) and acknowledged-or-unknown commands.
- **The techno is detected, the domain is declared.** `*.java` is observable; nothing in a repository says a project does IoT. That is *the* reason a project profile must exist — not a tooling convenience. `crew-dev` gains a **Step 0**: read the profile if supplied; absent, work on universal references only **and say so**, never assume defaults. The profile is also the first file to paste in paste mode.
- `docs/templates/house-rules.template.md` → `docs/templates/project-profile.template.md`, which also declares the domain and the stack. `/crew-project` generator **deferred** per the precedent of ADR 0006 and 0009: behavioral rule first, tooling when it leaks — and the only real need (a profile citing a vanished reference) is validation, not generation.
- **Activity-first indexing and the Skill+Agent pattern ([ADR 0014](./docs/adr/0014-activity-first-skill-agent-pattern.md))**: **17 skills → 5 commands** (`crew-dev`, `crew-review`, `crew-test`, `crew-architecture`, `crew-watch`). Reason: skills are invoked by hand, so the first level must be **what is known when the command is typed**. "I am developing" is known; "I am touching an audited entity and exposing an endpoint" is not — it is a property of code not yet written. `/persistence-craft` is a command nobody will ever type. ADR 0013 had put at invocation level information that does not exist at invocation; its taxonomy survives **one level down**, organising `crew-dev/references/`.
- **Graph composition**: skill → its references, skill → persona, persona → its references, persona or skill → another skill. The fourth edge removes a problem of the old structure — `crew-review` no longer fishes in a sibling skill's files to check conventions, it calls `agent-java` as a lens.
- **Loading by context, never by default**: a DTO loads `layering`, an entity loads `persistence`, an endpoint loads `api-rest`. Detection on observable facts (extensions, build files, annotations), not judgement; no matching row → say so and stop, never fall back silently on generic knowledge.
- **One persona, two modes**: `.claude/agents/agent-java.md` is a shell over `crew-dev/agents/agent-java.md`, the single source. Dispatched, it runs in an isolated context — what it adds beyond inline reading, and what makes it meet `doctrine.md`'s criterion. A full-stack feature dispatches `agent-java` and `agent-angular` in parallel with neither polluting the other's context nor the session's.
- **Normative / explanatory split**: moves from two files (`SKILL.md`/`best-practices.md`) to two sections of one reference file (`## Règles` / `## Pourquoi`). The asymmetry is unchanged and still decides: `## Règles` is right. ADR 0010 and ADR 0013 are **amended**, not replaced.
- **Structural routing check** added: every path `SKILL.md` cites must exist, every persona must have a detection row, every reference must be reachable. It found a real ambiguity on the first run — a `references/testfix.md` citation resolving against the wrong skill. The fresh-context routing test itself **was not run**: it remains due.
- `house-rules.md` consolidated into one gitignored file per skill, sectioned by domain.
- **Watch loop ([ADR 0010](./docs/adr/0010-watch-craft-maintenance-loop.md)) and `crew-watch` skill**: the ~700 lines of accumulated background had no ageing mechanism, and a stale reference is worse than none — it overrides fresher knowledge with the authority of a checklist. The ADR first settles the objection the July design raised against `best-practices.md` ("a second home for rules that already live in the skill"): **`SKILL.md` is normative, `best-practices.md` explains, and where they disagree the background is wrong**. Verifiable criterion: a MUST/NEVER present only in a background file is a defect. The `crew-watch` skill follows — doctrinal diff ("which existing rule becomes wrong?", not "is this interesting?"), routing of a finding by whether it changes the rule or only the reasoning, a dated digest in `docs/watch/`, and **one PR per impacted skill, never a direct commit**. Watch feeds are declared in `watch/references/sources.md`, distinct from the citations that ground a rule. `house-rules.md` files are out of scope: they are maintained by reading the employer's code, not by watch.
- **`kafka-craft`, `ws-craft` and `node-bff-craft` populated** — no skeleton left. `kafka-craft` states that ordering is a property of the **partition**, never the topic (so the key is the identity of what must stay ordered, and changing the partition count remaps every key), the delivery-semantics table with at-least-once as the honest default, and the two wrong exits for a poison message — infinite retry that blocks the partition, silent skip that loses data. `ws-craft` settles socket/SSE/HTTP before writing a line, explains why backoff **without jitter** turns a blip into an outage sustained by its own clients, why a reconnect resynchronises instead of resuming, and why an unbounded slow client is a server-side memory leak. `node-bff-craft` names the drift by small reasonable steps that ends with a business rule in the copy nobody audits, and why a timeout never means nothing happened — so no replay of a non-idempotent call.
- **`layering-craft` and `api-rest-craft` populated** — the two cross-cutting bricks that motivated the second axis. `layering-craft` settles "who maps" by the mechanical argument (mapping in the controller is mapping after the transaction closed, hence `LazyInitializationException`, and the two reflex fixes — `EAGER` and `spring.jpa.open-in-view`, enabled **by default** — are worse than the bug), separates the response model from the use-case output, and carries the anti-stacking counter-rule: a layer that transforms, protects or decides nothing exists only by symmetry. `api-rest-craft` sets a single error envelope (RFC 9457, which obsoletes 7807), status codes with the `400`/`422` dividing line, idempotency (including the idempotency key for retryable `POST`s), the compatible/breaking boundary, and OpenAPI style — `summary` without a trailing period.
- **`java-craft` deepened**: from 4 generic MUSTs to an enforceable checklist covering constructor injection and **Spring proxy semantics** (self-invocation, visibility, `final` — three silent ways to neutralise `@Transactional`/`@Cacheable`/`@Async`), modern Java carriers (`record`, `sealed` + pattern switch, `Optional` discipline), `@ConfigurationProperties`, centralised exception translation, parameterised SLF4J, and Spring test slices as the expression of `test-craft`'s criterion — same pattern as `angular-craft`, the doctrine applied to itself. The `references/best-practices.md` background is populated and sourced.
- **Duplicate test-tier rules removed** ([ADR 0008](./docs/adr/0008-skills-first-doctrine.md)): `test-craft` now owns the tier *criterion*, stated generically, and `angular-craft` keeps only its Angular *expression* (`.spec.ts`/`.cy.ts`, tooling, artifact list). The repair revealed a leak the other way — `test-craft`, meant to be agnostic, listed Angular/NgRx artifacts (`guards`, `pipes`, `interceptors`, `reducers`, `effects`) unusable for Java or Kafka — and a third copy of the disabled-suite rule, removed from `angular-craft`. `angular-craft`'s BFF exclusion now points to `node-bff-craft` rather than `security-review`.
- **Doctrine aligned with the migration.** [ADR 0012](./docs/adr/0012-claude-library-over-marketplace.md) records the replacement of the marketplace by the `.claude/` library and **supersedes [ADR 0001](./docs/adr/0001-plugin-marketplace-format.md)**, whose *context* was wrong, not only its decision. [ADR 0013](./docs/adr/0013-craft-skill-taxonomy.md) records the craft-skill taxonomy: four families indexed by topic, two language-agnostic axes, and the two distinct rules of placement and granularity. [ADR 0009](./docs/adr/0009-model-routing.md) is narrowed to environments where the model can be chosen.
- **`docs/SPEC.md` squared up**: header (16 skills, 4 agents, zero plugins), §1 (agents no longer qualified by a plugin; `dev-loop` loads one craft skill *per axis touched*, plus one per language), §2 (no more "when installed", no more `crew.sh` as a functional entry point), §3 (catalog rewritten: Family column instead of Plugin, the 6 new skills, explicit `skeleton`/`parked` status), §6 and §7. New **§9 — Consumption modes**: what paste mode imposes (a file's size is a contract, name references are dead links) and above all what it does not reproduce — neither isolation nor tool restriction, so nothing mechanically stops the model from grading its own work.
- **Out of the plugin format: the library replaces the marketplace.** The 10 skills and 4 agents move from `plugins/crew-*/` to `.claude/skills/` and `.claude/agents/`, auto-discovered by Claude Code with no install. The 7 `plugin.json` and `.claude-plugin/marketplace.json` are removed. Reason: the real usage context forbids installing plugins and choosing the model, which falsifies the context of [ADR 0001](./docs/adr/0001-plugin-marketplace-format.md) — one consumer, no installing client. Access depth to a skill goes from 4 levels to 3.
- **Six new skills**, on two language-agnostic axes: `layering-craft` and `persistence-craft` (structure), `api-rest-craft`, `kafka-craft` and `ws-craft` (exposed contracts), plus `node-bff-craft` filling a hole — the Node BFF was excluded from both `java-craft` and `angular-craft`. `persistence-craft` is populated and serves as the format reference; the other five are skeletons marked `TO POPULATE`.
- **`references/` convention per craft skill**: `best-practices.md` (the pattern and its reason, publishable, maintained by watch) and `house-rules.md` (employer-specific names and choices, **gitignored** — only `docs/templates/house-rules.template.md` is committed, to avoid leaking internal conventions).
- **Placement doctrine** recorded in [`docs/doctrine.md`](./docs/doctrine.md): where a rule goes (the axis that survives a techno change), a file's granularity (what fits a paste window), and an agent's existence (what it cannot do, or what it has not seen).
- **BMAD out of the repository**: 490 files and ~4.3 MB, untracked by git, duplicated internally (`plugins/.claude/skills` and `plugins/.agents/skills` strictly identical) and already available elsewhere. It was also scoped to `plugins/`, which the migration emptied of crew work. The `plugins/` directory disappears entirely; `doctrine.md`, `skill-manifest.csv` and the template move up to `docs/`.
- `README.md` rewritten: the marketplace, the `/plugin install` procedures, version pinning and the layout described an organisation that no longer exists.
- Everything removed is moved to `.attic/` (gitignored), not deleted, until the migration is validated.
- **Skills-first doctrine** ([ADR 0008](./docs/adr/0008-skills-first-doctrine.md)): `agent-crew-dev` and `agent-crew-critic` slimmed to shells — their MUST/NEVER content moved into `dev-loop`/`testfix` and `code-quality`/`security-review` respectively, so the same skills loaded solo (no agent, no dispatch) now produce identical behavior. `agent-crew-butler` reviewed and kept as the one deliberate exception (documented in its own file and in `docs/SPEC.md`): routing and multi-phase user gates need real dispatch mechanics no skill can reproduce.
- `code-quality`/`security-review` OUTPUT reconciled with the doctrine above: both skills now state their own `docs/reviews/<slug>.md` destination again, framed skill-first ("write this yourself in solo mode, or contribute this section when `agent-crew-critic` runs both") rather than agent-first. This intentionally revises the earlier N8 audit fix (which had removed the path to keep the skill "portable") — the reconciliation is: state the destination on the skill's own terms, not phrased as "feeds into agent-crew-critic," so solo mode gets a real destination without re-introducing a crew-internal assumption.
- `code-quality` gains a `docs/adr/` conformance check in its MUST (previously only stated on the now-slimmed `agent-crew-critic`); `security-review` gains an escalate-critical-findings-first MUST; both gain a never-silently-downgrade-a-finding NEVER.
- `angular-craft` enriched with generic Angular/TypeScript/RxJS/accessibility/testing rules (OnPush, standalone, built-in control flow, `takeUntilDestroyed`, no `any`, `afterNextRender`, keyboard parity with `(click)`, Vitest-vs-Cypress tier guidance) absorbed from the user's personal best-practices reference; client-specific items (a particular UI kit, monorepo tool, i18n file naming) were deliberately excluded — those belong in the client project's own `CLAUDE.md`.
- `scripts/crew-doctor.sh`: `REQUIRED_PLUGINS` gains `crew-tester`.
- `scripts/crew.sh`: new menu option "6) Test verification (independent)"; choice 5 (full flow) now includes an `agent-crew-tester` verification phase when `crew-tester` is installed, folded into the existing sanity-check gate rather than adding a new phase.
- `.claude-plugin/marketplace.json`: 7 plugin entries (adds `crew-tester`); `crew-core`/`crew-dev`/`crew-critic` descriptions reframed as shells for their skills.
- `plugin.json` version bumps: `crew-core` `0.2.0` → `0.3.0`, `crew-dev` `0.1.0` → `0.2.0`, `crew-critic` `0.1.0` → `0.2.0`, `crew-front-angular` `0.2.0` → `0.3.0`.

### Fixed

Contract defects found by an adversarial audit ([`docs/reviews/audit-v2-agents.md`](./docs/reviews/audit-v2-agents.md)); finding IDs in parentheses:

- `agent-crew-butler` had no `Write` tool despite `docs/SPEC.md` naming it the sole writer of `docs/adr/` and `docs/design/` (B1, B3). Fixed: `tools:` gains `Write`, scoped by a NEVER bullet to those two paths only ([ADR 0007](./docs/adr/0007-butler-topology-and-write-scope.md)).
- ADR 0004's "mechanically impossible" claim was false while `Bash` (which can write files) remained in the butler's and critic's allowlists (B2, N5). Fixed: reworded to an honest claim scoped to `Edit` specifically; the `Bash` bypass is now a recorded known gap, closed by a new NEVER bullet on both agents ("never use Bash to create or modify files").
- The `crew-architecture` skill never named a destination path for the ADRs/design notes it's supposed to anchor (B4). Fixed: its MUST now names `docs/adr/<slug>.md` and `docs/design/<slug>.md` explicitly.
- `crew.sh` choice 1 (both variants) auto-chained implementation straight into the critic's review, violating the "phases never auto-chain" rule in `docs/SPEC.md` §2 (B5). Fixed: both variants now insert an explicit STOP before dispatching `agent-crew-critic`.
- `docs/SPEC.md` §4 mislabeled the butler's read of `docs/reviews/` as its "sanity check"; the real sanity check runs earlier, on `agent-crew-dev`'s conversational evidence report, which no file in the table carried (S1). Fixed: relabeled to "relaying the verdict"; the table now states the evidence report is conversational-only.
- SPEC said the butler "routes" (implying subagent dispatch); README said "the main session is the orchestrator" — two different topologies, and a dispatched-subagent butler can't hold a live dialogue (S2, S4).
